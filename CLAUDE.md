# Кредитный конвейер МСБ — правила для ИИ-агентов

Прототип для хакатона Альфа-Банка. Клиент проходит путь от потребности до результата по заявке, банк обрабатывает заявку в том же продукте. Устройство проекта — в README.md.

## Жёсткие правила кейса

- Клиентская часть — только веб. Мобильное приложение не делаем.
- В сдаваемой версии нет платных API, подписок, покупных данных и закрытых лицензий.
- LLM — только с открытыми весами, запуск локально. Основной сценарий обязан работать без LLM.
- Нет доступа к системам Альфа-Банка. ЕГРЮЛ/ЕГРИП, ФНС «Прозрачный бизнес», БКИ, подписание и выдача — локальные моки.
- Все данные синтетические: клиенты, компании, сотрудники, документы, заявки, финпоказатели.
- Сценарий целиком внутри продукта: без email, SMS, мессенджеров и звонков. Уведомления — в интерфейсе.
- Всё запускается в Docker одной командой. Версии зафиксированы lock-файлами.
- Скоринг (оценка риска) и кредитное решение — разные модули. Исходы: одобрение, иные условия, запрос информации, отказ.
- Данные заявки сохраняются между этапами, повторный ввод не требуется, статус меняется последовательно.
- Каждый новый сторонний компонент, модель или датасет — сразу в THIRD_PARTY_NOTICES.md.

## Бэкенд (Python, FastAPI)

- Слои: `api` (тонкие роутеры) → `services` (сценарии) → `domain` (чистая логика без БД). `domain` не импортирует `models`, `db`, `fastapi`.
- Статус заявки меняется только через `services/workflow.change_status` — он проверяет переход и пишет журнал.
- Новое правило или признак — с юнит-тестом в `tests/`. Перед коммитом: `pytest`.
- Схема БД меняется только миграцией Alembic.
- После изменения API: `python -m app.export_openapi` и во фронтенде `npm run api:types`.
- Зависимости: прямые — в `requirements.in`, точные версии — `pip freeze > requirements.txt`.

## Фронтенд (React, Feature-Sliced Design)

- Слои: `app → pages → widgets → features → entities → shared`. Импорт только из слоёв ниже.
- Соседние слайсы одного слоя не импортируют друг друга. Из чужого слайса — только через его `index.ts`.
- Типы API берём из `shared/api` (`Schemas['…']`), файл `schema.d.ts` руками не правим.
- Серверное состояние — TanStack Query; Zustand — только сессия и UI-состояние.
- Какие действия доступны клиенту, решает бэкенд (`available_actions`), а не фронтенд.
- Тексты интерфейса — на русском, простыми словами: пользователь не разбирается в банковских терминах.
