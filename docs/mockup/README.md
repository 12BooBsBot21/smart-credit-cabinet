# Макет финальной версии

Макет — это слой поверх работающего скелета. То, что уже работает, осталось настоящим. Недостающие функции финальной версии добавлены экранами на фиктивных данных. На каждом блоке рамка показывает статус и зону ответственности:

- **зелёная** — готово, работает на настоящих данных;
- **жёлтая пунктирная** — макет: интерфейс есть, данные фиктивные, нужна реализация;
- в подписи рамки — кто доводит: Фронтенд, Бэкенд или ML.

Рамки включаются и выключаются кнопкой «Разметка задач» в шапке; для демо жюри их выключаем. Полный список задач с тем, что нужно сделать каждому, — на странице **«Карта задач»** (`/map`, открывается без входа) и в `frontend/src/shared/config/tasks.ts`.

## Как устроено в коде

- Фиктивные данные отдаёт `mockRequest(data)` из `frontend/src/shared/lib/mock.ts` — с задержкой, как настоящий API. Когда бэкенд готов, в хуке слайса `mockRequest(...)` меняется на `http.get(...)`, интерфейс не трогаем.
- Рамка — `MockFrame` из `frontend/src/shared/ui/MockFrame.tsx`. Статус и ответственные берутся из реестра `tasks.ts`: доделали блок — поменяли статус там.
- Где искать заглушки: `entities/feed`, `entities/ai-insight`, `entities/conveyor-stats`, `entities/document`, `features/notifications`, `features/upload-documents`, колонки SLA в `pages/bank-queue`.

## Как посмотреть вживую

Запуск — по корневому README (`python dev.py` в `backend/` и `npm run dev` в `frontend/`). Сценарий:

1. Войти как ИП Соколова → лента на главной.
2. «Новая заявка» → «Закупить товар» → кредит без залога, 2,5 млн ₽ на 12 мес. → иные условия и объяснение от ИИ.
3. Войти как андеррайтер → «Дашборд» → «Очередь» → карточка заявки.
